# Soryuka — Memory Mirror на главной

**Источник идеи:** [gnufoo/agent-mirror](https://github.com/gnufoo/agent-mirror) — граф памяти ИИ с 3D-орбитой, группами, вспышками и лентой событий. Его оригинальный сервер работает с Markdown/OpenClaw + WebSocket `ws`, а оригинальная визуализация загружает Three.js и d3-force-3d с CDN.

По просьбе владельца **главная Soryuka `/` теперь полностью отдана графу**, остальные панели (чат, память, настройки, развитие) не удалены и доступны на `/console.html`. Это самостоятельная реализация визуального принципа — не копия чужих исходников и не отдельный агент.

## Результат

| Адрес | Содержимое |
|---|---|
| `http://127.0.0.1:<ui-port>/` | Полноэкранная 3D-проекция локальной памяти, без старых карточек/чата |
| `http://127.0.0.1:<ui-port>/console.html` | Весь ранее существовавший интерфейс, включая чат Cloud.ru и настройки |
| `GET /api/mirror/graph` | Реальные узлы/связи SQLite + файлы канона + маркеры курсоров |
| `GET /api/mirror/activity?audit_after=N&message_after=M` | Новые реальные записи аудита/диалогов без приватного текста |

**Запуск:** `START-SORYUKA.bat` — тот же Python API и Node.js, одна SQLite, без Docker/Ollama и без новых зависимостей. В офлайне карта и все локальные функции работают. Без Cloud.ru чат по-прежнему не генерирует ответ.

## Как составляется граф

- **Сорюка** — центральный узел, **реальные файлы канона** `character/*.json` и `SORYUKA_INSTRUCTIONS.md` — подтверждённая структура проекта.
- **Категории** (узлы-контейнеры): память, диалоги, история, обучение, развитие, навыки. Эти категории — часть схемы данных, а не выдуманные личные воспоминания.
- **Личные воспоминания** читаются из `memories`, а подтверждённые связи — из `memory_links` и `causal_links`. Сведения, оспоренные владельцем, отображаются с явной меткой `owner_disputed` и не становятся «истиной» в чате.
- **Разговоры и обращения:** `sessions`, ограниченный набор `messages`, `memory_episodes`. При удалении информации узлы исчезают после следующей синхронизации.
- **События, цели, стратегии и локальные задания:** `story_events`, `study_goals`, `academy_strategies`, `growth_tasks`; оценки навыков — реальные агрегаты `feedback`.

Основные размеры выборки ограничены для защиты быстродействия (до 280 воспоминаний, 240 сообщений и т.д. на снимок). **Статистика показывает отображаемый поднабор, не обязательно весь размер SQLite при очень большой базе.** Для большого графа потребуется дополнительная выборка/кластеризация.

## Анимация работы ИИ

- Во время явного запроса в Cloud.ru сервис записывает событие `mirror_chat_started` в уже существующую таблицу `audit`: показывает реальные затронутые воспоминания, **не модельные мысли**.
- После успешного ответа записываются две реальные реплики `messages` и `mirror_chat_response` с метаданными обращения. В журнале появляются новые строки, в графе — импульсы и траектории между узлами.
- Остальные события читаются из существующего локального аудита — запись/удаление памяти, изменение связей, результат проверки навыка, завершение фоновой задачи.
- Отображение обновляется через обычные GET-запросы с интервалом 3 секунды; новые данные графа — каждые 15 секунд или после появления событий. **Ни одного нового Cloud.ru вызова ради анимации.**
- Кнопка **«✦ Импульс»** запускает только локальный визуальный пример; не записывается как настоящее действие ИИ.

## Управление

Левая кнопка + движение — вращение ракурса. Правая кнопка (или Shift+движение) — перемещение камеры. Колесо — масштаб. Наведение — подсказка, клик — карточка узла, кнопка «Показать связи» — фокус на нём. Доступны поиск по названиям, выбор категории, включение подписей и связей, автовращение, сброс. Для клавиатуры: +/− для масштаба, ←/→ для поворота, Escape для сброса выбора. При включённой настройке уменьшенного движения отключаются автоматические эффекты.

## Технологии

- `core/mirror_graph.py`: построение из SQLite, чистое чтение, агрегация событий.
- `core/server.py`: два новых маршрута только через существующую токенную защиту.
- `core/soul_engine.py`: два неинвазивных события старта и завершения чата. Их запись **best-effort**: техническая ошибка отображения не блокирует уже оплаченный ответ.
- `ui/mirror.js` и `ui/mirror.css`: независимая от библиотек Canvas-реализация пространственной проекции; **это не реальный движок Three.js/WebGL и не полная копия upstream**, а похожая по внешнему виду интерактивная 3D-ориентированная карта.
- `ui/console.html`: прежний интерфейс сохранён с без изменений его основных скриптов.
- `ui/server.mjs`: отдельные статические маршруты с той же защитой происхождения запросов и localhost-прокси.
- `tests/test_mirror_graph.py`: проверки честного источника, связей, пустой памяти, приватности событий и API.
- Существующие тесты Soryuka 4/5 проверяют `console.html`, а не новые полотна `index.html`.

## Приватность

Нет CDN, Google-авторизации, OpenClaw watcher, доступа к домашним каталогам, постоянного внешнего WebSocket-сервиса, выгрузки переписок в git, передачи графа третьим лицам. Данные остаются на `127.0.0.1` и в SQLite. В событиях не хранится текст личного сообщения; названия узлов отображают ограниченные фрагменты локальных сообщений, доступные только пользователю этого компьютера.

## Лицензия и ссылки

У `gnufoo/agent-mirror` в README написано MIT, но в `package.json` указана ISC, а отдельного `LICENSE` файла в корне нет. Поэтому **исходный код и визуальные ассеты upstream сюда не скопированы**; эта версия написана для Soryuka с использованием открыто описанной концепции графа памяти. У Soryuka своя лицензия пока не установлена; не путать с upstream.

## Проверки

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
python character/living_personality_runtime.py
node --check ui/server.mjs
node --check ui/app.js
node --check ui/mirror.js
```

CI должен проходить на Windows и Linux. Для реального визуального QA запустить BAT на своём ПК и проверить Canvas в Edge/Chrome; юнит-тесты не заменяют скриншотную проверку внешнего вида.
