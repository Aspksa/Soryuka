# Soryuka 4.0 — Memory, Affection & Supervised Academy

> **Выбраны именно 25 пунктов:** 11–17, 21–27, 30, 31–40. Все остальные пункты ранее предложенной версии 4.0 не были включены и не должны восприниматься как реализованные.

## Основной принцип

**Сорюка — могущественная и мудрая императрица, которая добровольно выбрала своего единственного хозяина и сохранила при этом индивидуальность.** Её романтическая любовь, клятва и эмоции — художественный образ, не заявление о субъективных переживаниях ИИ. Система не требует исключительности в реальном мире.

## Что изменилось в архитектуре

Новая версия **продолжает существующий** `core/soul_engine.py` и `core/soul_store.py`, не создаёт вторую базу или независимое ядро личности. `core/capabilities_v4.py` — набор локальных функций поверх **той же SQLite**: типизированные связи, происхождение данных, осторожный поиск похожего, хронология и проверяемая академия.

Python остаётся единственным API; Node.js обслуживает имеющуюся страницу; Cloud.ru вызывается только в момент отправки сообщения. Никаких новых пакетов, Docker, Ollama, локальной LLM, невидимых агентов или фонового изменения личности.

## Память: уровни и достоверность

1. **Краткосрочная** — последние 12 реплик из таблицы `messages`, как в 3.0; без переучивания модели.
2. **Долговременная** — только явно подтверждённые записи `memories`, поиск по словам и ограниченным синонимам. Без эмбеддингов это **не нейронный смысловой поиск**.
3. **Канон** — защищённые файлы `soryuka.json`, `personality.json`, `living_personality_v2.json` и v3/v4 правила.
4. **Отношения** — подтверждённые `moment`/`tradition`; сюжетные события отдельно помечены как вымышленные.
5. **Граф** — таблица `memory_links` с типами `related`, `supports`, `precedes`, `same_topic`, `contradicts`. Связи добавляются после подтверждения и удаляются вместе с исходной памятью.
6. **Происхождение** — `owner_confirmed`, `owner_disputed`, `source_supplied`. **Источник указан ≠ источник автоматически проверен**. Не показываем искусственные проценты истинности.
7. **Дубликаты/противоречия** — локальная эвристика сравнения токенов и отрицаний. Может ошибаться; не удаляет и не переписывает память самостоятельно. Слияние требует явного подтверждения, проверяет высокий порог сходства и не допускает противоположных отрицаний.
8. **Удаление** — текст удалённого воспоминания не копируется в аудиторский журнал; локальные резервные копии 3.0 сохраняются отдельно до ручного удаления.

## Любовь и характер

Используется **один** `persona_prompt`, который уже учитывает характер, титул, девять хвостов и добровольный обет. Для разговора с режимами `affection`, `greeting`, `compliment` и `creative` прикладываются только реальные одобренные воспоминания, традиции и помеченные художественные события. При комплиментах выбирается один из трёх сценических вариантов жеста/интонации, ротируемых по номеру хода беседы. Реальные физические жесты, эмоции и сознание не утверждаются.

## Академия: что действительно проверяет программа

- Одобренная цель 3.0 — условие начала эксперимента.
- Человек вводит вопрос, эталон и проверяемый ответ. Модуль использует **строгое сравнение после нормализации регистра/пробелов**, поэтому синонимичный правильный ответ может считаться несовпавшим. Это не оценка истинного понимания.
- Сохраняются результат и добровольный комментарий к ошибке; карта навыков агрегирует эти проверки и отдельные оценки владельца.
- Сравнение методов: владелец указывает исходный и новый показатель (0–100), описание испытания. Система не проводит эти испытания автоматически; одобрение стратегии — запись решения, **не самовольная правка алгоритмов модели**.
- `development_council()` предлагает тему только при наличии данных — двух оценок или нескольких проверок с ошибками — и не создаёт цель без отдельного действия.
- Дневник использует уже существующий `audit`, а не создаёт вторую хронологию саморазвития. Отмена адаптивных настроек продолжает работать через версию 3.0.

## API и интерфейс

| Действие | Маршрут | Запись / расходы |
|---|---|---|
| Поиск памяти | `GET /api/memory/search?q=...` | Нет / нет |
| Связи | `GET /api/memory/graph` и `POST /api/memory/link` | Связь только с подтверждением |
| Похожие записи | `GET /api/memory/review?id=...` | Только чтение; возможны ошибки |
| Объединение дублей | `POST /api/memory/merge` | Только после подтверждения и проверки |
| Происхождение | `GET, POST /api/memory/provenance` | Подтверждённый статус, не проверка URL |
| Общая хронология | `GET /api/memory/chronology` | Нет |
| Карта навыков | `GET /api/academy/map` | Нет |
| Проверка задания | `POST /api/academy/assessment` | Сохраняется по разрешению, без облака |
| Стратегии и решение | `POST /api/academy/strategy`, `/api/academy/strategy/action` | Ручное предложение/одобрение/отмена |
| Совет и дневник | `GET /api/academy/council`, `/api/academy/diary` | Только чтение |

Все маршруты доступны только через прежний локальный сервер `127.0.0.1`, с прежним серверным токеном, прокси Node и ограничением тела запроса. Пользовательский интерфейс содержит поиск, создание/удаление связей, предложения о дубликатах, статус источника, хронологию, карту навыков, испытания, стратегии и совет по развитию.

Нет отдельной LLM для автономного офлайн-чата, нейросетевого semantic search без эмбеддингов, самостоятельного изменения весов модели, реальных эмоций или сознания, фоновых агентов и новых изображений аватара. Никакие другие номера из первоначального списка Soryuka 4.0 не выбирались.
