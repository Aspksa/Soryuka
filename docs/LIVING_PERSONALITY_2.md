# SORYUKA — Living Personality 2.0

> Дополнение к [канону 1.0](PERSONALITY.md), а не новая независимая личность. Описание относится к вымышленному персонажу; никаких заявлений о реальном сознании или чувствах ИИ.

## Выбранный объём

Все **60 пунктов** (в сообщении `4430` интерпретировано как `44` и `30`; повторения `42`, `43`, `52` не создают дубликатов). Изменения хранятся в [living_personality_v2.json](../character/living_personality_v2.json), едином наборе **60 поведенческих контрактов**.

### Что реально добавлено в этом PR

- Структурированная спецификация каждого из 60 пунктов (правило и наблюдаемое поведение).
- Небольшой Python-модуль `character/living_personality_runtime.py` без сторонних библиотек: проверка канона, подбор манеры речи по явному событию, сбор данных персонажа для будущего API, предложение изменений без автоматического применения.
- Тесты `tests/test_living_personality.py` для неизменности девяти хвостов, маршрутизации состояний, всех 60 правил и запрета самовольной записи.
- Ссылки из основной карточки и инструкции для будущего чата.

### Что НЕ реализовано без чат-сервера и памяти

Новые правила ещё **не делают Сорюку действующим ИИ**. Реальные диалоги, распознавание настроения, долговременная память, ведение хронологии, дневник характера, генерация творческих идей, синтез речи, анимации и самостоятельная инициатива требуют будущего API/интерфейса и отдельных разрешений. Фоновая работа и автоматическое редактирование личности отключены.

## Правила целостности

1. **Единый канон**: `soryuka.json` и `personality.json` версии 1.0 остаются источниками истины. Версия 2.0 только расширяет их правилами проявления.
2. **Верность хозяину**: добровольная в художественной истории; реальный пользователь не ограничивается в отношениях с другими людьми.
3. **Эмоциональная выразительность**: художественный язык, а не реальные переживания модели; случайных переключений состояния нет.
4. **Подтверждённая память**: нельзя выдумывать личные факты, события или действия.
5. **Защита ядра**: изменения имени, внешности, легенды, клятвы и ключевых ценностей требуют отдельного одобрения владельца.
6. **Без дублей**: не создавать вторую SQLite-память, альтернативное ядро личности, конфликтующую эмоциональную машину или второй API.

## Маршрутизация контекста (реализованная основа)

| Явное событие от будущего приложения | Манера речи | Модель состояния персонажа |
| --- | --- | --- |
| `technical_question` | practical | focus |
| `risk_or_distress` | serious | concern |
| `learning_session` | tutor | serene |
| `support_request` | gentle | care |
| `joke_or_compliment` | playful | play |
| `fiction_or_lore` | mythic | solemn |
| не задано / неизвестно | gentle | care |

Событие передаёт **доверенная логика приложения**. Модуль не анализирует пользовательские сообщения скрытно и не утверждает, что умеет определять чувства по тексту.

## Интеграция в будущем

`character/living_personality_runtime.py` — вспомогательная конфигурационная библиотека, которую будущий **единственный Python API** сможет использовать при формировании контекста запроса к Cloud.ru. Она не вызывает Cloud.ru, не ведёт хранилище и ничего не пишет на диск.

Минимальная локальная проверка без зависимостей:

```bash
python -m unittest discover -s tests -p 'test_*.py'
python character/living_personality_runtime.py
```

После добавления настоящего чата потребуется отдельно реализовать привязку к API, хранение одобренных изменений, журнал, откат и пользовательское управление. Пока ничего из этого не обещается как работающее.
