# Soryuka — 3D-граф следующего этапа

**Выбранные пункты:** 3, 11, 12, 15, 17, 19, 20, 21, 23, 24, 26.

Это усовершенствование существующей 3D-карты на базе Three.js, d3-force-3d,
Python API и одной SQLite. Чат, канон личности, интерфейс `/console.html`,
настройки графики и локальный запуск сохраняются.

## Реализация выбранных пунктов

| № | Возможность | Реализация |
|---|---|---|
| 3 | Защита от чёрного экрана | Ранний `mirror-bootstrap.js` проверяет WebGL, обнаруживает загрузочные ошибки и тайм-аут сцены; контекст WebGL может быть восстановлен с перезагрузкой. Есть ссылка на чат. |
| 11 | Адаптивные FPS | Измерение кадров каждые ~2 секунды; три уровня качества с гистерезисом, автоматическое ограничение devicePixelRatio, уменьшение числа видимых дальних листьев и детализации геометрии. |
| 12 | Глубокий туман | Настоящий `THREE.FogExp2` плюс три атмосферных слоя декоративных световых частиц, зависящих от существующего ползунка плотности. |
| 15 | Физика узлов | 3D-коллизия с увеличенными границами для центрального ядра/кластеров; проверенные расстояния, 2 итерации пересечений, ограничение шагов на кадр. |
| 17 | Рост карты | Добавленные **реальные** записи SQLite располагаются около своих связанных групп и получают короткий визуальный импульс. Уже существующие узлы сохраняют координаты. |
| 19 | Потоки информации | По подтверждённой связи из SQLite или по фактически выбранным источникам контекста проходят 3D-частицы. Нет искусственных событий памяти. |
| 20 | Большие графы | Сохранение структуры при одинаковом наборе ID, геометрия низкого качества для дальних листьев, ограничение числа объектов, raycaster с лимитом частоты, фоновые вкладки не расходуют ресурсы. |
| 21 | Карточка узла | Клик показывает название, описание, происхождение, дату, состояние и связи из текущего графа. Тестовый импульс — отдельный режим. |
| 23 | Подсветка связей | Наведение и выбор выделяют только соседей и настоящие рёбра в текущем графе; список связанных узлов позволяет перейти к соседу. |
| 24 | Маршрут источников | Показаны только ID локальных записей, **выбранных Python для контекста запроса**. Это не доказательство внутреннего использования источника LLM. |
| 26 | Анимация ответа | Начало запроса и успешное сохранение ответа из SQLite-аудита отображаются разными импульсами по фактическим выбранным узлам. |

## Ограничения и безопасность

- Нельзя точно показать скрытое мышление модели, работу нейронных весов или
  правдивость ответов. Граф отображает **события Python/SQLite**, а не «мысли».
- Функция роста работает для реальных объектов, попавших в ограниченный снимок
  `core/mirror_graph.py`. При десятках тысяч записей нужна отдельная
  пагинация/агрегация. Не обещается отображение миллиона отдельных сфер.
- Уровень качества подстраивается по FPS, но не измеряет видеопамять и не
  гарантирует фиксированную частоту на всех видеокартах.
- 3 атмосферных слоя — декоративные частицы поверх глубинного тумана, а не
  физическая симуляция объёмного рассеяния света.
- При отключённом аппаратном ускорении WebGL-страница показывает диагностику;
  старый интерфейс чата остаётся доступен по `/console.html`.
- Строки из памяти/сообщений не вставляются в HTML как код — для карточки
  применяются `textContent`, без небезопасных HTML-атрибутов.
- Добавленные файлы не требуют новых npm/Python зависимостей или Cloud.ru-оплат.

## Проверка

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
node --check ui/mirror-original.js
node --test ui/graph-v2.test.mjs
node --test ui/graphics-settings.test.mjs
```

GitHub CI проверяет Python + Node на Windows и Linux. Реальная проверка
картинки и GPU требует браузера с WebGL; CI не заменяет визуальное тестирование
в интерфейсе пользователя.
